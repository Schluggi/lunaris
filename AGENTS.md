# AGENTS.md — Context for working on this repo

This file is for **AI and human agents** working on the project. **Please update this section when behavior, architecture, or conventions change materially**, so context stays accurate for later sessions.

## Purpose

**lunaris** is a **single Rust binary** that sends **Frozen** USART commands locally (without the Eight Sleep cloud): **Prime**, **SetTargetTemperature** left/right, **GetTemperatures** (**`0x41`** request, opensleep parity), and optionally **Vibration** on the **Sensor** UART (**SetAlarm** per side). Wire format **opensleep** ([LiamSnow/opensleep](https://github.com/LiamSnow/opensleep): CRC + `0x7E` framing).

Target hardware: **Eight Sleep Pod 4** — the protocol is modeled in code/repos after **Pod 3 / opensleep** and is **experimental on Pod 4**; differences (TTY, baud, commands) are possible — [`docs/usart-frozen.md`](docs/usart-frozen.md) (Frozen), [`docs/usart-sensor.md`](docs/usart-sensor.md) (Sensor vibration / capacitance).

**Deploy target:** Pod OS is **Linux aarch64** (e.g. “Eight Layer”, `uname -m` → `aarch64`). Releases must be built with **`--target aarch64-unknown-linux-gnu`** (or similar); see **README** and [`.cargo/config.toml`](.cargo/config.toml). Running native `x86_64` builds on the Pod → `Exec format error`.

## Architecture (brief)

| Module / path | Role |
|---------------|------|
| [`src/main.rs`](src/main.rs) | CLI, logging; **Frozen serial required** (`exit(1)` if not open); **Sensor serial optional** (vibration — warning if not open); LED I²C optional. Spawns **`frozen_link`** + optional **`sensor_link`** (long-lived USART owners), then `mqtt_bridge::run`. |
| [`src/cli.rs`](src/cli.rs) | **clap**: MQTT, topic/`--discovery-prefix`, Frozen + Sensor + I²C; **`--pod 3`/`4`/`5`** (**5** = same USART defaults as **4**) sets default bauds when **`--serial-baud`** / **`--sensor-baud`** omitted. No separate config file; device paths can follow **`/opt/eight/config/machine.json`**. `--vibration-*` CLI defaults were removed; vibration intensity/duration/pattern are runtime HA MQTT entities. HA discovery **`object_id`** values are fixed in [`mqtt_bridge`](src/mqtt_bridge.rs). |
| [`src/machine_config.rs`](src/machine_config.rs) | After parsing CLI, applies **`frozenPort`** / **`sensorPort`** from **`/opt/eight/config/machine.json`** when the file exists and the path was **not** set with **`--serial-device`** / **`--sensor-device`**. |
| [`src/deviceinfo.rs`](src/deviceinfo.rs) | Reads **`/deviceinfo/device-label`** and **`/deviceinfo/device-id`** on the host; MQTT text sensors publish **`{topic_prefix}/sensor/deviceinfo_device_label|device_id/state`** (**retained**; empty payload if a file is missing); HA discovery sets **`enabled_by_default`: false** (like **Firmware message**). |
| [`src/frozen_frame.rs`](src/frozen_frame.rs) | CRC + framing; Frozen: `prime_frame()`, `ping_frame()`, `jump_to_firmware_frame()`, `get_temperatures_frame()` (**GetTemperatures** `0x41`), `set_target_temperature_frame()`, … |
| [`src/frozen_rx.rs`](src/frozen_rx.rs) | Parses inbound Frozen payloads: `0x81` pong, `0x90` jump ack (wake state); **`0x41` TemperatureUpdate**, **`0xC1` GetTemperature** → MQTT current temps + heatsink (opensleep `frozen/packet.rs`); **`0x07` Message** (UTF‑8) → optional MQTT **Firmware message** text sensor (all lines); same messages also drive optional **Water Tank** for the two reservoir strings (opensleep `frozen/state.rs`). |
| [`src/frozen_link.rs`](src/frozen_link.rs) | **Opens Frozen UART once** — opensleep-style **wake** (`Ping` + `JumpToFirmware` every 2s until pong shows firmware), **keepalive** ping ~15s, queues MQTT frames (`mpsc`); forwards decoded temperatures, optional water-tank booleans, and optional **`0x07` text** to **`mqtt_bridge`**. |
| [`src/sensor_frame.rs`](src/sensor_frame.rs) | Sensor: `vibration_sequence_frames`, `piezo_priming_frames`, `set_alarm_frame()` (= opensleep `SetAlarm`). |
| [`src/sensor_rx.rs`](src/sensor_rx.rs) | Parses inbound **`0xAE` VibrationEnabled** (and related acks); required before `SetAlarm` works like opensleep’s state machine. Parses **`0x33` Capacitance** (opensleep `sensor/packet.rs`) → MQTT **occupancy** left/right: before calibration, **`--presence-cap-threshold`** on max-per-side; after MQTT **Calibrate presence** (or broker‑restored **Presence Baseline Zones**), opensleep‑style baseline + Δ + debounce. |
| [`src/wire_buffer.rs`](src/wire_buffer.rs) | If no `0x7E` yet, **retain** RX tail (do not `clear()`); avoids losing frames split across `read()` calls. |
| [`src/sensor_link.rs`](src/sensor_link.rs) | **Opens Sensor UART once** — RX decode, periodic **piezo priming**, optional forward of capacitance to MQTT, queues vibration: **priming → wait for `0xAE` → SetAlarm**. Frozen **Prime** over USART is handled in [`mqtt_bridge`](src/mqtt_bridge.rs). Piezo setup follows opensleep-style staggering (`CONFIG_RES_TIME`–style gaps in [`sensor_link`](src/sensor_link.rs)); upstream schedules individual commands instead of bulk periodic batches. |
| [`src/serial_prime.rs`](src/serial_prime.rs) | `check_device_accessible` at startup; **`send_frame` / `send_frames`** when **`frozen_tx`** / **`sensor_tx`** is unset (tests or fallback path in [`mqtt_bridge`](src/mqtt_bridge.rs)). |
| [`src/is31fl3194.rs`](src/is31fl3194.rs) | IS31FL3194 over Linux **I²C** (`i2cdev`), solid RGB — logic from opensleep `led/controller.rs` (GPL). |
| [`src/mqtt_bridge.rs`](src/mqtt_bridge.rs) | **rumqttc**: discovery Prime + MQTT **Request Temperatures** button (**diagnostic**; sends Frozen **GetTemperatures** request, payload **`0x41`** per opensleep **`FrozenCommand::GetTemperatures`**) + optional **Vibrate** + optional **`device_class`: occupancy** **Presence Left / Right** and **Presence Any** (ON if either side is ON) + optional MQTT **Calibrate presence** (**`button`**; entity_category **config**) — **`--presence-calibrate-secs`** (default **10**), opensleep **`sensor/presence.rs`** mean baseline + Δ (**50** default, tunable at runtime via MQTT **Presence Baseline Delta** **`number`**, MQTT `enabled_by_default`: **false** in HA), **5‑frame debounce**; optional MQTT **`device_class`: running** **Presence Calibration** binary sensor (**ON** during the calibration window — manual or automatic at startup when no retained **Presence Baseline Zones**); MQTT **Presence Cap Threshold** (**`number`**, max‑per‑side raw capacitance when uncalibrated; CLI **`--presence-cap-threshold`** or HA; MQTT `enabled_by_default`: **false** in HA); MQTT **Presence Baseline Zones** diagnostic **sensor** (JSON **`[z0…z5]`**, **retained** on broker → restored after lunaris restart like the two presence numbers — bootstrap drains retain before lunaris republishes) + optional **Water Tank** MQTT **binary_sensor** (**`device_class`: plug**; Frozen `0x07`; **ON** = reservoir present, **OFF** = removed) + optional **Firmware message** MQTT text sensor (`0x07` UTF‑8; diagnostic; MQTT `enabled_by_default`: **false** in HA) + **three Frozen temperature sensors** (HA names **Current Temperature Left/Right**, heatsink °C; state topics still `cover_temperature_*`) + **two target-temperature sensors** (HA **Target Temperature Left/Right**; state `…/sensor/target_temperature_left|right/state`, mirrors climate setpoint) + **climate left/right** (MQTT **`current_temperature_topic`** = same as each side’s `cover_temperature_*` state, see [climate.mqtt](https://www.home-assistant.io/integrations/climate.mqtt/)) + optional light + optional **Startup LED** switch (retained preference; green LED only when lunaris **starts** if ON); enqueues bytes to **`frozen_tx` / `sensor_tx`**; outbound in **`tokio::spawn`** (avoid deadlock with `poll()`). HA device **Firmware** is MQTT **`sw_version`**: **`Lunaris`** + semver (crate). |

Typical MQTT topics: `…/button/prime/set`, `…/button/request_get_temperatures/set`, `…/button/vibrate_left|vibrate_right/set`, `…/switch/vibration_cancel_preamble/set|state`, `…/button/calibrate_presence/set`, `…/number/presence_cap_threshold/set|state`, `…/number/presence_baseline_delta/set|state`, `…/sensor/presence_baseline_zones/state`, `…/binary_sensor/presence_left|right|any/state`, `…/binary_sensor/presence_calibration/state` (**`device_class`: running** — ON while **Calibrate presence** sampling runs, including auto-start when no retained baselines), `…/binary_sensor/water_tank/state` (**`device_class`: plug**), `…/sensor/firmware_message/state`, `…/sensor/deviceinfo_device_label/state`, `…/sensor/deviceinfo_device_id/state`, `…/sensor/cover_temperature_left|right/state`, `…/sensor/heatsink_temp/state`, `…/sensor/target_temperature_left|right/state`, `…/climate/…`, `…/switch/startup_led/set|state`, `…/result`, with payloads for the last two deviceinfo sensors read from **`/deviceinfo/device-label`** and **`/deviceinfo/device-id`** on the host when present.

**Standalone operation:** **`frozen_link`** / **`sensor_link`** replicate opensleep’s continuous MCU handshake and priming so Prime/climate/vibration work **without** another service (e.g. frankenfirmware) on the same TTY — **only one process may own each UART**.

**Frozen serial:** default **`/dev/ttyS1`** @ 38400 (Pod 4), or **`frozenPort`** from **`/opt/eight/config/machine.json`** when present (unless **`--serial-device`** is passed). **Water Tank** and **Firmware message** MQTT entities are always discovered; inbound **`0x07`** parsing drives them via **`frozen_link`**. **Sensor (vibration):** default **`/dev/ttyS2`** (or **`sensorPort`** from **`machine.json`** unless **`--sensor-device`**) @ **`921600`** with **`--pod 4`** or **`--pod 5`** when **`--sensor-baud`** is omitted; **`--pod 3`** → **`115200`**; **`--sensor-baud`** overrides — open failure → no vibration buttons **and** no capacitance presence. When the Sensor UART opens, MQTT discovers **presence**: before calibration, **`--presence-cap-threshold`** (default **800**, max‑per‑side; HA **Presence Cap Threshold** number updates at runtime) applies; after **Calibrate presence** (leave bed empty for the window — default **`--presence-calibrate-secs`** **10**) baselines apply like opensleep (per‑zone average, Δ from **`--presence-baseline-delta`** default **50** or HA **Presence Baseline Delta** number, **5** successive frames touching any zone on a half). Successful **Calibrate presence** recomputes and **retained**‑publishes **Presence Cap Threshold**, **Presence Baseline Delta**, and **Presence Baseline Zones** (`…/sensor/presence_baseline_zones/state` as JSON **`[z0…z5]`**) so the broker keeps them across restarts.

**HA settings persistence:** After **MQTT connect**, lunaris runs one **bootstrap** window (~850 ms) while **`mqtt_ha_state_bootstrap`** is active: subscribed **retained** **`state_topic`** traffic repopulates in-memory HA entities — **climate** left/right **mode** + **setpoint**, **MQTT light** **`…/light/led/state`** JSON snapshot, vibration **number/select/switch** states, presence numbers + baseline zones (**Sensor** UART / presence entities as configured). Startup then **enqueues** Frozen `SetTargetTemperature` for both sides so the MCU matches recovered climate, mirrors states to MQTT, applies vibrate/presence publishes, then applies LED (HA light retain, or startup-green when the **Startup LED** switch retained **ON**). Later inbound **`state_topic`** echoes (except startup LED retained sync) are ignored so **`command`** updates stick. **`--presence-debug`** logs every capacitance **`0x33`** inference at **INFO**, **WARN every 60 s** if no sample reaches occupancy yet, and a **once-only Sensor WARN** on the first CRC-valid **`0x33`** rejected by opensleep layout (**Pod 4** layout may differ). (raw six zones, uncalibrated `left_max`/`right_max` vs **`--presence-cap-threshold`**, or calibrated baseline + per-zone debounce) while debugging HA **clear**. On startup, **`sensor_link`** always runs an opensleep-style **bootloader handshake** (38400 Ping + JumpToFirmware, then opens firmware baud). **`--sensor-vibrate-no-ack-wait`** skips waiting for inbound **`0xAE`** (for Pods where RX is not opensleep-framed at the chosen baud). **Alarm cancel** before each vibrate follows the HA **Vibration Cancel Preamble** switch (default **on**). Each vibrate sends EnableVibration + piezo setup + SetAlarm (optionally prefixed by cancel **`SetAlarm`**, matching opensleep). HA discovers MQTT switch **Vibration Cancel Preamble** (`enabled_by_default`: **false**; entity_category **config**).

**LED:** I²C **`/dev/i2c-1`**; probe error → no light. With LED enabled, HA discovers a **Startup LED** switch: retained preference **`…/switch/startup_led/state`**. Turning it **ON/OFF does not change the hardware immediately**; if **ON** is stored at the broker, lunaris sets the LED **solid green once per process start** (after subscribing, using broker-retained state). MQTT **reconnect** in the same run does **not** re-apply startup green (one-shot hardware apply per lunaris process). On exit (**SIGINT** / **SIGTERM** / MQTT loop stop), the LED is turned **off**.

## Conventions for changes

- **Git commits (Conventional Commits / semantic-release style):** Use [Conventional Commits](https://www.conventionalcommits.org/) so messages work with **commitlint** and match what **semantic-release** expects — e.g. `feat:`, `fix:`, `docs:`, `chore:`, `ci:`, `refactor:`, `test:`, `perf:`; breaking changes via `feat!: …` or a `BREAKING CHANGE:` footer. This repo does **not** run the npm **semantic-release** tool; [`.github/workflows/release.yml`](.github/workflows/release.yml) does a **patch** version bump on push to **`main`/`master`** only when there is at least one **`feat:`** or **`fix:`** commit since the previous tag (**`workflow_dispatch`** always releases); major/minor are not driven by commit types.
- **Language:** User-facing text (Home Assistant discovery names, README, `docs/`, CLI help) is **English only**.
- **License:** GPL-3.0 ([`LICENSE`](LICENSE)). Code/framing traceable to opensleep → keep attribution/source notices in affected files.
- **Scope:** Stay focused (no large drive-by refactors). Add new features (TLS, more entities) deliberately and document them.
- **Tests:** **Unit-test** critical logic (CRC, frame bytes); CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml): `fmt`, `test`, `clippy`; separate job **aarch64** `release` cross-build) runs on **pull requests** only. On **push** to **`main`/`master`**, [`release.yml`](.github/workflows/release.yml) publishes **only if** there is a **`feat`** or **`fix`** commit after the last tag (otherwise the workflow succeeds without publishing). **`workflow_dispatch`** always runs the full release. When a release runs: patch bump in **`Cargo.toml`**, Git tag **`v*.*.*`**, GitHub Release with **aarch64** Linux binary (+ **`SHA256SUMS`**); release notes list commits from the previous tag to the new tag (**no merge commits**, no **`chore(release):`** bump); not GitHub’s PR-based auto notes.
- **Toolchain:** [`rust-toolchain.toml`](rust-toolchain.toml) — **clap** is pinned to `=4.5.27` (compatibility with Rust 1.84; newer clap may require Rust 1.85+/Edition 2024).
